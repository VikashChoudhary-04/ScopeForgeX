# ScopeForgeX Demo Assessment — OWASP Juice Shop

## Overview

This directory contains a sample FAST-profile assessment generated by
ScopeForgeX against a locally hosted OWASP Juice Shop instance.

The example demonstrates ScopeForgeX's assessment workflow, including
scope validation, reconnaissance, HTTP attack-surface discovery,
vulnerability assessment, raw-output preservation, and report generation.

## Target

- **Application:** OWASP Juice Shop
- **Target:** `192.168.13.128:3000`
- **Profile:** `fast`
- **Target Type:** `web`
- **Environment:** Authorized local lab

## Assessment Workflow

The example follows the ScopeForgeX assessment lifecycle:

1. Scope validation
2. Reconnaissance
3. Enumeration
4. Vulnerability assessment
5. Finding collection and normalization
6. Report generation

The FAST profile is designed to provide a quick, high-value assessment
with reduced execution scope and request volume.

## Generated Output

### Reconnaissance

The `recon/` directory contains reconnaissance artifacts produced during
the assessment.

It includes:

- `hosts_raw.txt` — Raw discovered host data
- `hosts_alive.txt` — Hosts that responded during validation
- `hosts_final.txt` — Final validated host set
- `urls_raw.txt` — Raw discovered URLs
- `urls_final.txt` — Final validated URL set

### Vulnerability Assessment

The `vuln/` directory contains vulnerability-assessment artifacts.

It includes:

- Nuclei JSONL results
- Nuclei host and URL scan output
- Vulnerability findings
- Scanner logs
- Vulnerability summary data

These files preserve the underlying scanner output rather than treating
scanner results as the final report.

### Reports

The assessment produces both human-readable and machine-readable reports:

- `report.md` — Human-readable assessment report
- `report.json` — Machine-readable assessment data

## Result Summary

The captured example assessment contains:

| Metric | Result |
|---|---:|
| Hosts discovered | 1 |
| URLs discovered | 1 |
| Automated findings | 0 |

An automated finding count of zero does **not** imply that the target is
secure. Scanner coverage depends on the selected profile, enabled
capabilities, available evidence, and detection rules. Manual analysis
remains necessary for vulnerabilities that require contextual or
application-specific reasoning.
